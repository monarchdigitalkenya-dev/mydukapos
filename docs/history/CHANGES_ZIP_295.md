# Zip 295

- **Store history is its own tab** (`store-history-tab`, button right after Store) in Shop, Hotel, Hospital, Pharmacy, Production and Services: summary cards, an action filter (All / Sold / Withdrawn / Added / Qty / Edited / Deleted) and search. It is no longer a panel at the bottom of the Store tab (Hotel, Hospital, Pharmacy and Production never had it). Registered in tab locks, the sidebar Business group, print-panels and the Hotel storekeeper / Hospital pharmacist + inventory roles.
- **Sell from Store (Sales Counter, all six apps):** a purple "Sell from Store" button opens the Store list (name, code, in-store quantity, price). Choosing item + quantity takes it out of the Store through the server's atomic `removeFromStore` (purpose "taken to the sales counter"), credits this branch and puts it in the cart. When the sale is recorded the Store history gets a **Sold** line (`logSale`, idempotent on the sale id; a retry queue covers a lost connection).
- **Store parity:** Hotel, Hospital, Pharmacy and Production now run the same Store tab and Store code as the Shop (price column, item editing, quantity correction, print report, delete, code-first matching on a transfer - the older apps matched on name only).
- Server: `functions/api/store.js` and `_store-d1.js` gain `logSale`; `removeFromStore` accepts `purpose`. New block `src/shared/blocks/store-sales.html`.
- **Purchases (Shop):** arrival of serialized items asks for the identifiers first (stock only rises when they match the count); variant lines; a drawer-paid purchase writes one cash movement. **Cash:** exempt-from-reconciliation button, branch + device assignment, Cash drawer report.
- **Server-side permission guard** (`_perm-guard.js`) on the cash and serial lists for both the KV and Durable Object backends; active only when staff sessions are in `enforce` mode.
- **Hotel - Post order:** an order a waiter posts is always visible to that waiter, even on a table another waiter opened (`hospTabAllowed` also checks who posted a round). Test: `hotel-post-order-visible-293`.
- **Sales Counter - Delivery popup (all 7 apps, block `delivery-popup.html`):** the Delivery button opens the delivery form as a wide popup with every field (client, address, zone, phone, fee, free delivery, cost, agent, payment); Done keeps the sale a delivery with an Edit summary bar; Walk-in instead closes it. Test: `delivery-popup-293`.
- **Store - Import from inventory:** a variable item (sizes / colours) imports as one Store line per variant ("Tee (Red / M)", code `TEE::v1`); taking it credits that exact variant. Import rows no longer depend on the item code being safe inside an element id.
- Service-worker version `zip-295`. Tests: `store-sales-293` (8), `purchases-cash-292` (5), `perm-guard-292` (4).
- Known limits: sale attribution to Store stock is first-in-first-out per item code; a pay-later bill is logged when it settles; a voided sale is not yet written back to the Store history; Water has no Store; the full 390-file suite was not run in the build sandbox.
