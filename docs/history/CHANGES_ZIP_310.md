## Zip 310 - Multi-branch Phases 2 and 3: stores, stock moves, transfers between branches, HQ dashboard, reports, roles

- **Stock in Business HQ:** stores per branch (main store, warehouse, kitchen / bar / pharmacy store), receive into a store, count a store, **move between a store and the shop floor** (branch total unchanged, no sale or purchase created, reversible). Server: `functions/api/_stock.js`, `_xfer-actions.js`; tables in the transaction database (`migrations/0016_stock.sql`, also created on first use).
- **Transfers between branches:** request -> approve (rules: every / above a value / never; the requester cannot approve their own) -> dispatch (stock leaves the source; checked inside the branch database so it can never oversell) -> in transit -> receive (part receipts, damaged, missing) -> settle (write off, returned, found) -> completed. A retry or two people pressing at once never moves stock twice. References TR-00001 / MV-00001; full history per transfer.
- **Dashboard** (opens first): sales today / 7 days per branch, staff, low stock with the till's own rule, transfers waiting, latest movements and HQ activity.
- **Reports:** sales, stock (shop floor, stores, in transit), transfers and discrepancies, staff; one branch or consolidated; CSV download (formula-safe). Administrators only see their branches.
- **Roles:** templates (Branch manager, Supervisor, Cashier, Store keeper, Accountant, Auditor) and custom roles, given per person per branch; manager roles only by the owner; no self-change.
- Report: `docs/MULTIBRANCH_310.md`. Tests: `zip310-stock-transfers` (7), `zip310-hq-reports` (3), `zip310-hq-stock.browser` (Shop desktop, Hotel phone); `zip309-business-hq.browser` updated (HQ now opens on the Dashboard). Service worker zip-310.
