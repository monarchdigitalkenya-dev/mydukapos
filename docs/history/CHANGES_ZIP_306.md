## Zip 306 - Lower Cloudflare cost, same sync speed

- **"Anything new?" over the open connection.** A device with a healthy live connection used to ask the server over HTTP every ~30 s even when nothing had changed (router Worker + Pages Function + shop database each time). It now sends a tiny `v?` message on the connection it already has; the shop's live-sync room (SyncRoom) answers with the newest version it knows, and the device pulls over HTTP only when that version is newer than its own - at once, not at the next tick. A 3-minute HTTP backstop stays. Incoming WebSocket messages are billed at 1/20 of a request and need no Worker, no KV and no database. Measured in the tests: 5 quiet minutes on two devices = 0 HTTP pulls (was ~20).
- **The shop database tells the room after every change**, whichever endpoint made it (sync push, booking, cross-branch sale, import); single-record shops note it on every write. Reads never do. Instant pushes ("poke") are unchanged (still a bare poke, so an old cached app can never mistake it for data).
- **Nothing gets slower and every fallback is the old behaviour:** connection down -> HTTP every ~7 s; router not updated yet / room never answered -> HTTP every 30 s; hidden tab -> 5 minutes. All 7 apps (Water has its own poll tick, also updated). Fixed on the way: Water could read its synced version as 0 because it may hold `pos_last_synced_at = '0'` next to its own key.
- **Edge cache for licence and subdomain lookups** (Cloudflare Cache API, free, shared by the Worker instances of a data centre): a freshly started instance no longer reads them from KV. 30 s window (inside KV's own ~60 s spread), an owner change puts the new value at once, not-found is never kept. `EDGE_CACHE_MS=0` switches it off.
- **Permanent shops already live in their own database** (moved automatically at their first push since zip 156), so a sale writes nothing to KV; now covered by a test.
- **Router config:** `npm run deploy:router` first runs `tools/ensure-router-config.mjs`, which adds the router's own `SYNC_ROOM` binding to `wildcard-router\wrangler.toml` if it is missing (nothing else in the file changes; your account ids stay).
- **Licence certificate (PDF):** the warning "Anyone with the link can open the shop" is replaced by a reassuring, true note: your data travels over a secure connection, is stored encrypted and backed up regularly; only you and the staff you add can sign in, with your password or their PIN.
- Tests: `zip306-live-sync` (real Shop app on two devices + real server, shop database and live room: sale on A shows on admin B also when the instant push is lost; restock +2 reaches B, never goes back, never adds again, also after a refresh; B selling from an old copy -> both count; stock matches on A, B and server after mixed sales/restocks; zero HTTP checks while quiet; fallbacks; all 7 apps wired), `zip306-room-version`, `zip306-edge-cache`, `zip306-kv-writes`. Service worker zip-306.
