# Changelog

Per-zip detail lives in `docs/history/CHANGES_ZIP_*.md`.

## Zip 397
- **KV cost: the print network moved off KV.** Every open till re-registered itself every 20 s and the server rewrote the shop's whole device list in KV each time (a billed KV write per till every 20 s, all day), and a till with a printer polled its job queue every 4 s (2 KV reads, plus a write every 10 s).
  - The device list and the job queues now live in D1 (`LEDGER_DB`; new migration `0021_print_relay.sql`, and `print-relay.js` creates the two tables itself if the migration has not run). The first use carries the KV device list over once. If D1 is not bound or fails, the old KV keys are used, so printing never stops.
  - Tills heartbeat every 60 s (was 20 s); a heartbeat that changes nothing writes nothing; a device counts as online for 2.5 minutes after it was last seen (was 30 s).
  - Measured over one simulated shop hour (3 tills, 1 printer till, 30 receipts): KV writes 810 -> 0, KV reads 2,461 -> 31 (the routing rules, read once per receipt); 30 sent, 30 printed, all 3 tills online.

## Zip 396
- **Capture List "signal is aborted without reason" fixed** (all 8 apps). Since zip 335 every API call without its own time limit was cut off after 25 s (so a bad network never leaves a screen stuck); reading a photo with the AI often takes longer, so the read was cancelled and the browser's raw message was shown. Now:
  - AI calls (`/api/ai-...`: Capture List photos, menus, past sales) get 2 minutes; everything else keeps 25 s (`device-security.html`).
  - A time-out says it in plain words ("Reading took too long. Check the internet connection and try again." / "The server took too long to answer...") on every screen.
  - The photo is shrunk to at most 1600 px (JPEG) before it is sent (new shared `shrinkImageDataUrl`): a 15 MB phone photo goes as about 0.9 MB, so it uploads and reads much faster.
  - Capture List errors read in plain words (too long / no connection) instead of the browser's text.
- Checked in a real browser: the AI answering after 30 s -> the list opens, no error; 15.3 MB photo sent as 0.93 MB (1200 x 1600).

## Zip 315 - A phone stuck on "Syncing" catches up by itself (no new messages)
