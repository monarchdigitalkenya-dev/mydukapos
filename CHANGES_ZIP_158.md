# Zip 158

## Adjust receipt size (receipt letter size, replaces "Print Scale")

**What the shop sees.** Settings ▸ Receipt Settings now has one **🔠 Adjust receipt size** button (it replaces the "Paper Width" select and the "Print Scale" slider). It opens a full-screen window:
1. **Paper** — big 58 mm / 80 mm / Custom buttons (custom: 30–300 mm). It edits THIS device's printer paper when the till has its own (Settings ▸ "THIS device's printer paper", still there), otherwise the shop's paper width.
2. **Letter size** — a big number in points with − / + (steps of 0.5) and a typed box, 5–20 pt, starting at the saved size; chips 7 (standard) 8 9 10 11 12; shows "N characters per line".
3. **Sample receipt** — the real receipt builder (`buildReceiptDoc`) drawn on a box exactly as wide as the paper, with the shop's name / logo / stamp / QR / footer / alignment, 4 sample items, VAT, TOTAL, cash + change, reference + barcode. It redraws on every tap.
4. **🖨️ Print test receipt** (the real path: system dialog, USB, Bluetooth, print relay; one copy; no cash drawer; uses the UNSAVED paper and size), **Save** (stores + syncs, toast "Receipts will now print at N pt on X mm paper"), **Cancel**, **Reset to standard** (7 pt).

**How it works.**
- New setting `receiptFontPt` (5–20, step 0.5, default **7 = exactly what receipts looked like before**). Stored `pos_receipt_font_pt`; synced with the shop's other receipt settings (it rides in `extraSettingsCollect/Apply`, so every app incl. Aqua, the branch-group shared receipt settings and new devices get it). A device only sends a size it has of its own — a fresh device's default never replaces the shop's.
- The size **drives the columns**: `getPaperCols()` = floor(printable width / (0.6 × letter size × 1.005)) → 32 on 58 mm and 48 on 80 mm at 7 pt, fewer for bigger letters, more for smaller. The grid is drawn at exactly that size (`--rg-font`), so nothing can overflow. There is no auto scale-to-fit any more (`fitReceiptGrids` removed). At 7 pt a custom roll never gets more columns than a text-mode printer holds (1.5 mm a character). Very narrow layouts (fewer than 30 columns) stack each item (name, qty × price, amount).
- **Thermal ESC/POS**: at 7 pt the text bytes are byte-for-byte what they were (a test compares hashes with the pre-change output for all 7 apps at 58 and 80 mm). At any other size the receipt (and kitchen tickets / reports through `buildEscPosBytes`) is drawn on a canvas (Courier New, columns from `ctx.measureText`), thresholded to 1 bit and sent as GS v 0 raster bands of ≤ 200 rows, width = printable dots (58 mm → 384, 80 mm → 576, custom → round(printable mm × 8)); bold header / TOTAL / payment rows, centred header and footer, logo, stamp, reference barcode and cut are kept. The print relay gets a long receipt as several jobs cut on band boundaries (each ≤ 140 KB, cut only in the last) — never truncated. No canvas → the text bytes and a toast.
- **Removed**: the Print Scale slider, `receiptScale`, `pos_receipt_scale` / `aqua_receipt_scale` (deleted silently on load), `--receipt-print-zoom` and the `zoom:` print CSS, the scale field in the branch-group snapshot. Server: `receiptFontPt` is a stamped whole-value setting in `_merge.js`; an old app that still sends `receiptScale` is accepted and the value is dropped.
- Paper width limits are now 30–300 mm everywhere (were 30–120 for the per-device override).

**Files.** `src/shared/functions.js` (getPaperCols, receiptFontPtNow, receiptTrialRun, raster builders, relay jobs, `receiptSize*`), `src/shared/blocks/receipt-size.html` (new: the window), `src/shared/blocks/receipt-extras.html` (setting store + sync), `tools/lib.mjs`, each app's Settings HTML / size functions / snapshot / `buildEscPosBytes`, `functions/api/_merge.js`, `tools/build-guides.mjs` (+ `npm run guides`), `tests/receipt-size.test.mjs` (new), `tests/print-engine.browser.test.mjs` (no `fitReceiptGrids`).

**Not verified on real hardware.** Everything is tested in jsdom with a fake canvas: the look of the letters on real thermal paper (thresholding, bold weight, real Courier New metrics), Bluetooth speed for a picture receipt (about 6 KB/s over BLE: a 10 pt receipt of ~60 KB takes ~10 s), real print dialogs and the full-screen window on phones were not exercised in a browser.
