# MyDuka CRM — inspection, architecture and API contract (zip 157)

## 1. What exists today (inspection)
- **Hosting**: Cloudflare Pages (static apps + `functions/api/*.js`), KV `mydukapos_kv`, D1 `LEDGER_DB` (`mydukapos-ledger`, real SQLite semantics; tests run it on `node:sqlite` via `tests/d1-fake.mjs`), Durable Objects in `wildcard-router/`. Apex `mydukapos.store` = public site + Owner Console (`owner/index.html`); client shops live on subdomains.
- **Owner auth**: ONE owner account in KV (`owner-account:v1`), signed session tokens `o2.<rand>.<iat>.<hmac>` (`functions/api/_owner-auth.js`, `requireOwnerAuth(context)`), stored client-side as `localStorage.pos_owner_session_token` on the apex origin. `/crm/` is the same origin, so an owner already signed in to the console is signed in to the CRM.
- **Existing Leads** (Owner Console "📋 Leads" tab, `owner/index.html` ~L2035, L2320-2500, L4736+; API `functions/api/leads.js`): a day-sheet per date in KV `leads-sheet:<YYYY-MM-DD>` (lead: id, name, phone, product, status/contacted/dead/meeting flags, contactedBy…), meetings list `leads-meetings`, name-only staff list `leads-staff-list`, and a WhatsApp click-to-ad inbox `leads-whatsapp-inbox` filled by `functions/api/whatsapp-webhook.js` + `_whatsapp.js` (signature check `WHATSAPP_APP_SECRET`, verify token `WHATSAPP_VERIFY_TOKEN`). "Closed" = a real MyDuka client was generated (`generateLink` → `_license.js createClient`). No real users, no permissions, no DB.
- **Staff (POS)**: per-shop staff with PIN sessions (`_staff-auth.js`) — shop-scoped, NOT reusable as CRM identities.
- **Products**: MyDuka products (`_license.js PRODUCTS`: shop, hotel, hospital, production, pharmacy, …) = what CRM leads are prospects for. **Sales/orders**: POS sales are per client shop (ledger tables) and are the *clients'* takings, not MyDuka's revenue → CRM keeps its own `crm_sales` and links a converted lead to the MyDuka client record (license id) it creates.
- **Rate limiting**: KV counters (`_ratelimit.js`). **Integrations**: WhatsApp Cloud API inbound webhook (ad leads only), SMS, M-Pesa, etims.

## 2. CRM architecture
- Static app at `/crm/` (own `index.html`, `crm.js`, `crm.css`, manifest; NOT part of the POS tabs). API under `/api/crm/*` via one catch-all Pages Function `functions/api/crm/[[path]].js` dispatching to modules in `functions/api/_crm/`.
- **Data**: D1 `crm_*` tables (FKs, indexes, `PRAGMA foreign_keys` on), schema in `functions/api/_crm/schema.js` (single source, created on first use like the ledger; `migrations/0002_crm.sql` generated by `tools/gen-migration.mjs` — extend it — with a test that they agree). Timestamps = epoch ms UTC; business "today" = Africa/Nairobi.
- **Identity**: `crm_users`. The MyDuka owner (owner token) is auto-provisioned as the `owner` CRM user (`owner_ref='owner'`). Staff sign in with email+password → CRM token `c1.<userId>.<iat>.<hmac>` (HMAC key derived from a server secret `CRM_SESSION_SECRET` if set, else from the owner account salt/hash, plus the user's `session_epoch`; bumping the epoch (password change/suspend/reset) revokes all that user's tokens). **Status and permissions are read from the DB on every request**, so suspension is immediate. Passwords: PBKDF2-SHA256 (100 000 iterations, per-user salt); never returned. Invitations/reset: single-use random token, only its SHA-256 stored, 7-day expiry; the admin gets a link, never a password.
- **Permissions**: catalogue of keys (leads.view/create/edit/delete/assign/claim/import/export, staff.view/add/edit/deactivate/roles, campaigns.view/create/edit/revenue, revenue.own/team/company, reports.own/team/company, settings.manage/integrations/products/statuses, inbox.view/reply, meetings.manage, followups.manage, sales.record, audit.view). Roles give defaults (owner = all; manager; sales); per-user `grant`/`deny` overrides. Sales staff scope: own leads + unassigned pool only; team/company figures need revenue.team/company, reports.team/company. Every endpoint enforces server-side (object-level too: a URL/ID change never widens access).
- **History is never deleted**: staff are deactivated/suspended/"removed" (= inactive + archived) — rows stay; lead ownership history in `crm_lead_owners`; every activity keeps `user_id` plus a `user_name` snapshot.
- **Claim** is one conditional `UPDATE crm_leads SET owner_id=? … WHERE id=? AND owner_id IS NULL` — the row count decides the winner.
- **Attribution** is captured once into `crm_attribution_events` (every touch kept) and the lead's `first_*` fields (original source/campaign/ad set/ad) are never overwritten; a returning lead adds an event. Missing fields stay NULL — nothing invented. CPL/CPA/ROAS only when spend > 0.
- **Duplicates**: normalised phone (E.164-ish, Kenyan default 254), whatsapp, lower-cased email; manual create returns 409 with matches unless `force`; imports classify per row.
- **Imports**: staged (`crm_imports`, `crm_import_rows`), commit runs in ≤200-row batches per call.
- **WhatsApp**: inbound via the existing Meta webhook (`whatsapp-webhook.js`, same signature check) now writes conversations/messages into CRM (ad-referral attribution recorded; non-ad chats also kept as conversations, linked to a lead only when the number matches or an ad referral exists — a lead is created for ad-referral chats). Outbound replies use the Cloud API only if `WHATSAPP_TOKEN` + `WHATSAPP_PHONE_NUMBER_ID` are set, else the API answers `whatsapp_not_configured` and the UI says so (wa.me/tel: links still work). Meta Lead Ads webhook `/api/crm-meta-webhook` resolves leads via Graph only if `META_PAGE_TOKEN` is set; otherwise the event is stored as unresolved.
- **Public capture**: `POST /api/crm-lead` — validates, honeypot field, per-IP + global KV rate limit, size caps, phone normalisation, dedupe, attribution, notification; no internal data returned.
- **Legacy migration**: owner-only `POST /api/crm/legacy/migrate` (idempotent by `legacy_id`, `dryRun`), `GET /api/crm/legacy/verify` (counts). Maps day-sheet leads → `crm_leads` (source `whatsapp` if it came from the inbox, else `legacy`; created/contacted timestamps, contactedBy → historical staff name snapshot, statuses, meeting flags → status/meetings), meetings → `crm_meetings`, staff-list names → archived `crm_users` (`login disabled`) so history keeps a name, inbox messages → conversations. Website signups (`demo-account-index:v1`) -> `website` leads (`demo:<email>`; registered-only accounts as New with a note); `demo-account.js` also pushes new signups live (`_crm/demo-lead.js`). `functions/api/leads.js` (the old Leads API) has been removed. Nothing in KV is deleted. Unmappable fields go to `crm_leads.legacy_json` and are listed in `CRM_MIGRATION.md`.
- **POS untouched** except: Owner Console loses the Leads tab/code/API calls (after migration is verified) and gains one "Open CRM" link; `whatsapp-webhook.js` feeds the CRM.

## 3. API contract (all JSON; `Authorization: Bearer <owner-or-crm token>`; errors `{error, code}` with 400/401/403/404/409/429)
Auth: `POST /auth/login {email,password}`→`{token,user}` · `GET /me`→`{user:{id,name,email,phone,role,perms[],photo,status},config}` · `GET /auth/invite?token=`→`{name,email,role}` · `POST /auth/invite/accept {token,password,name?,phone?,photo?}`→`{token,user}` · `POST /auth/reset/accept {token,password}` · `POST /auth/password/change {current,next}`.
Staff: `GET /staff` · `POST /staff {name,phone,email,role,department?,photo?,perms?}`→`{user,inviteLink}` · `GET /staff/:id` (profile+stats) · `PATCH /staff/:id` · `POST /staff/:id/status {status:'active'|'suspended'|'inactive'}` · `POST /staff/:id/reset-link`→`{link}` · `POST /staff/:id/reassign {toUserId|null, leadIds?|all:true}` · `POST /staff/:id/remove` · `GET /staff/:id/activity` · `GET /permissions`→`{keys[],roles{}}` · `PUT /staff/:id/permissions {grant[],deny[]}` · `POST /staff/:id/role {role}`.
Config: `GET /config`→`{statuses[],classifications[],sources[],lostReasons[]}` · `PUT /config/:kind {items:[{id?,key?,label,color?,active,isWon?,isLost?}]}` (ordered; keys stable; deactivate, never delete).
Leads: `GET /leads?q&status&class&staff&source&campaign&adset&ad&product&from&to&follow=today|overdue|none|upcoming&revenue=won|none&pool=1&sort&dir&page&pageSize`→`{items,total,page,pageSize}` · `POST /leads {contact…,force?,mergeInto?}`→201 lead|409 `{duplicates:[lead…]}` · `POST /leads/check-duplicates` · `GET /leads/:id`→`{lead,products,timeline,followups,meetings,sales,owners,attributions,conversation}` · `PATCH /leads/:id` · `POST /leads/:id/claim|assign {userId}|status {status,lostReason?}|classification {value}|note {text}|contact {method,outcome?,notes?}|products {productIds[]}|convert {productId,quantity,unitPrice,discount,paymentStatus,createClient?}|merge {intoId}` · `POST /leads/bulk {ids[],action:'assign'|'status'|'classification',value}` · `GET /leads/export.csv`.
Follow-ups: `GET /followups?bucket=today|overdue|upcoming|completed&staff` · `POST /leads/:id/followups {dueAt,type,notes,remindMinutes?}` · `PATCH /followups/:id` · `POST /followups/:id/complete {notes?}`. Meetings: `GET /meetings?from&to&staff` · `POST /leads/:id/meetings {startsAt,durationMin,type,location,link,notes}` · `PATCH /meetings/:id` · `POST /meetings/:id/status {status:'scheduled'|'confirmed'|'completed'|'rescheduled'|'cancelled'|'no_show', startsAt?}`.
Products: `GET/POST /products`, `PATCH /products/:id`. Campaigns: `GET /campaigns` (tree + metrics) · `POST /campaigns` · `PATCH /campaigns/:id` · `POST /campaigns/:id/adsets` · `POST /adsets/:id/ads` · `PATCH /adsets/:id`, `/ads/:id` · `POST /campaigns/:id/spend {date,amount,adsetId?,adId?}`.
Sales: `GET /sales?from&to&staff&product&campaign&ad&source` · `GET /sales/:id` · `PATCH /sales/:id {paymentStatus}`.
Dashboard: `GET /dashboard?range=today|yesterday|week|7d|month|lastmonth|custom&from&to&staff`. Reports: `GET /reports/staff|sources|campaigns|products|funnel|response?from&to&staff&source&campaign&product`.
Inbox: `GET /inbox/conversations?q&unread&mine` · `GET /inbox/conversations/:id/messages` · `POST /inbox/conversations/:id/messages {text}` · `POST …/note {text}` · `POST …/read` · `POST …/link {leadId}` · `GET /inbox/status`→`{apiConfigured}`.
Imports: `POST /imports {fileName,source,mapping,options:{duplicates:'skip'|'update'|'create',assign:{mode:'none'|'one'|'csv'|'roundrobin'|'equal',userIds[]}}}`→`{id}` · `POST /imports/:id/rows {rows:[{...}]}` (≤500) · `GET /imports/:id/preview` · `POST /imports/:id/commit`→`{done,processed,total}` (call until done) · `GET /imports/:id` · `GET /imports/:id/errors.csv` · `GET /imports` · `GET /imports/template.csv`.
Other: `GET /notifications` · `POST /notifications/read {ids|all}` · `GET /audit?entity&user&action&from&to&page` · `GET/PUT /settings`. Public/other: `POST /api/crm-lead`, `GET|POST /api/whatsapp-webhook`, `GET|POST /api/crm-meta-webhook`, owner-only `POST /api/crm/legacy/migrate`, `GET /api/crm/legacy/verify`.

## 4. Risks
KV eventual consistency (avoided: CRM state is D1-only) · D1 not bound → CRM API answers `503 crm_database_missing` (never silently falls back) · Pages catch-all routing precedence (`/api/crm/[[path]]` must not shadow `/api/crm-lead`) · legacy data volume (batch inserts) · PBKDF2 iteration cap on Workers (100 000) · WhatsApp/Meta features need the operator's tokens — shown as "not connected" until configured, never faked.

## 5. Implementation notes (backend, as built)
- **Files**: router `functions/api/_crm/router.js` (called by `functions/api/crm/[[path]].js`), modules in `functions/api/_crm/` (`schema, core, auth, config, scope, notify, attribution, leads, followups, sales, staff, campaigns, reports, inbox, imports, misc, meta, legacy`). Public: `functions/api/crm-lead.js`, `functions/api/crm-meta-webhook.js`; `whatsapp-webhook.js` also feeds the CRM. Migration SQL is generated (`npm run gen:migration` -> `migrations/0002_crm.sql`; a test fails if it drifts from `schema.js`).
- **Response naming is camelCase** everywhere (`ownerId`, `firstTouch`, `paymentStatus`...). Lead detail returns `{lead, products, timeline, followups, meetings, sales, owners, attributions, conversation}`; the lead's original attribution is `lead.firstTouch`, every touch is in `attributions`.
- **Invite / reset links** are `${CRM_BASE_URL or request origin}/crm/?invite=TOKEN` and `/crm/?reset=TOKEN` (the frontend must read these two query params; tokens are random 64 hex, only their SHA-256 is stored, 7 days, single use).
- **`leads.all`** is an added permission key: without it a user sees their own leads plus the unassigned pool (sales default); managers and the owner have it. Assign / bulk / staff-wide filters need it.
- **Session tokens**: `c1.<userId>.<iatBase36>.<hmac>`, keyed by `CRM_SESSION_SECRET` (falls back to a key derived from the owner account) and the user's `session_epoch`; suspend / restore / password change or reset bump the epoch (a role or permission change needs no new token, as permissions are read per request). Permissions are read from D1 on every request.
- **Extra routes** beyond the contract: `DELETE /leads/:id` (soft delete, refused when the lead has sales), `GET /campaigns/:id`, `POST /integrations/meta/resolve` (retry unresolved Meta leads), `GET /inbox/status` -> `{apiConfigured}`.
- **Reminders without a scheduler**: `sweepReminders` runs at most once a minute (gated by a conditional upsert on `crm_meta.sweep`) when `/me`, `/notifications`, `/dashboard` or `/followups` is called. Notifications are de-duplicated with keys, so each follow-up produces one "due" and one "overdue" notification per recipient.
- **Bulk action body**: `{ids[<=200], action:'assign'|'status'|'classification', value, lostReason?}` -> `{results[{id,ok,code?,error?}], ok, failed}`.
- **Claiming**: guarded `INSERT ... WHERE EXISTS` chain plus the partial unique index `uq_crm_lead_one_owner`; the loser of a race gets `409 already_claimed` and leaves no history rows.
- **WhatsApp without D1**: the webhook keeps working through the old KV inbox path (existing tests rely on it); the CRM API itself answers `503 crm_database_missing`.
- **Environment**: `CRM_SESSION_SECRET`, `CRM_BASE_URL`, `CRM_PUBLIC_ORIGINS`, `CRM_LEAD_IP_LIMIT`, `CRM_LEAD_GLOBAL_LIMIT`, `META_APP_SECRET` (else `WHATSAPP_APP_SECRET`), `META_VERIFY_TOKEN` (else `WHATSAPP_VERIFY_TOKEN`), `META_PAGE_TOKEN` (optional, Graph lookups), `WHATSAPP_TOKEN` + `WHATSAPP_PHONE_NUMBER_ID` (optional, outbound chat).
